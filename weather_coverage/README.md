# Исследование покрытия OpenWeather

Петропавловск-Камчатский, проект моделирования зимнего содержания дорог. Исходная география и полный план сеток подготовлены. Фактический пилот выполнен. Синтетический пример доступен отдельно. Статус фактического сбора и рекомендации приведены в [отчёте](REPORT_RU.md), описание продуктов и тарифов — в [справке об API](API_CAPABILITIES.md).

## Установка

Из корня репозитория на macOS или Linux с Python 3.11+ выполните:

```bash
python3 -m venv /tmp/pkc-weather-venv
source /tmp/pkc-weather-venv/bin/activate
python -m pip install -r weather_coverage/requirements.txt
```

Все команды ниже запускаются из корня репозитория. Генерация географии использует локальные файлы проекта. Для карты браузер загружает библиотеки Folium/Leaflet и подложку OpenStreetMap, для чего нужен интернет. Геометрия воды и дорог хранится в самом HTML и служит подложкой при недоступности тайлов. Карта открывается как обычный локальный HTML, сервер не требуется.

## Воспроизведение географии и демонстрации

```bash
python -m weather_coverage coordinates
python -m weather_coverage demo
python -m weather_coverage map --source demo
```

[coordinates.geojson](coordinates.geojson) содержит городскую границу, рабочую маску, ориентиры районов, прямоугольники сеток и точки. Координаты WGS84 записаны в порядке долгота, широта в геометрии и в отдельных атрибутах `longitude`, `latitude`. В каждой занятой ячейке предусмотрена точка на рабочей маске. `shifted_from_cell_center` показывает смещение от центра ячейки. `cell_ids` содержит привязку точки к трём размерам сетки. Метка `pilot` задаёт выборку для первого этапа. Район указан при точной привязке к ориентиру или попадании в один из нанесённых полигонов; для остальных точек поле пустое. `elevation_m_dsm` — интерполированная высота Copernicus и пустое значение вне охвата имеющегося тайла.

[weather_coverage.html](weather_coverage.html) открывает слои границ, воды, основных дорог, районов, сеток и точек. При наличии погодных строк можно выбрать продукт, время и параметр, включить ближайшие пары и совпавшие численные профили. Пустые поля обозначены серым. Оттенки привязаны к диапазону выбранного среза. Панель показывает источник данных.

[spatial_analysis.ipynb](spatial_analysis.ipynb) содержит выполненный анализ фактических данных, графики и точные правила сравнения. Для запуска командой:

```bash
jupyter nbconvert --to notebook --execute --inplace weather_coverage/spatial_analysis.ipynb
```

Для синтетического примера измените `SOURCE` в ноутбуке на `"demo"`. Перед первым использованием проверьте, что Python-ядро Jupyter использует окружение со всеми зависимостями.

## Фактический пилот

Задайте ключ бесплатного плана в окружении процесса с помощью менеджера секретов или интерактивного ввода. В zsh:

```zsh
read -rs 'OPENWEATHER_API_KEY?Ключ OpenWeather: '
export OPENWEATHER_API_KEY
```

```bash
python -m weather_coverage collect --round pilot-next
python -m weather_coverage map --source openweather
```

Первичный срез `pilot-01` вернул HTTP 401 по обоим продуктам. В повторном срезе `pilot-02` авторизация прошла и получены ответы со всех 23 точек по обоим продуктам. Затем `dense-01` получил Forecast для 48 точек. В журнале использовано 96 из 100 попыток. [Отчёт о пилоте](REPORT_RU.md)

У пилота 23 точки и два продукта, для полного среза потребуется до 46 запросов. Повтор с тем же `--round` и параметрами использует уже учтённые координаты и ответы. Новый погодный период требует нового ID среза. `--endpoints weather` или `--endpoints forecast` ограничивает сбор одним продуктом. При HTTP 429 дождитесь сброса квоты перед следующим срезом. HTTP 401/403 блокирует дальнейшие запросы к продукту. Для явной перепроверки доступа запустите новый срез с `--recheck-access`. Прежние попытки сохраняются в общем бюджете. При повторном отказе клиент снова прекращает запросы к этому продукту.

[observations.csv](observations.csv) содержит только нормализованные фактические строки. [observations_demo.csv](observations_demo.csv) содержит только синтетические строки. В таблице указаны точка, координаты и ID города из ответа API при наличии, продукт, срез, время запроса, срок действия, заблаговременность прогноза, интервал накопления, код явления, погодные поля, список пропусков и относительный путь исходного JSON. Запись среза выполняется из постоянного журнала. Подлинные успешные ответы хранятся без форматирования в `.state/raw/<round>/`, попытки — в `.state/ledger.sqlite`. Каталог исключён из Git. Ключ не записывается в данные или журнал.

### Бюджет и плотный этап

Для повторного полного сбора после завершённого эксперимента используйте отдельный журнал, сохранив текущий каталог `.state` как архив вместе с соответствующим CSV.

Бюджет **100 HTTP-попыток на весь эксперимент** фиксируется при первом разрешённом сборе в журнале. Чтобы задать другое число, передайте `--budget N` в первый запуск. Ошибки и прерванные запросы расходуют бюджет, чтение кэша его не расходует. Один запрос начинается не чаще чем раз в 2,05 секунды, с учётом предыдущих запусков этого журнала. Сбор учитывает собственные попытки, поэтому другие приложения с любым ключом этого аккаунта уменьшают доступный запас общей квоты. В коде доступны только Current и Forecast из общего бесплатного плана. Переходы по редиректам, автоматические повторные запросы и подключение подписок отключены.

Плотный этап запускается отдельно. Для допуска инструмент проверяет, что в фактическом пилоте есть сравнимый точный срез с минимум тремя наземными точками и хотя бы одной ненулевой разностью в пределах 2 км по температуре, скорости ветра или осадкам. Это скрининг для дополнительной проверки. План с числом запросов выше остатка отклоняется целиком. В примере для сетки 500 м выбираются 20 точек. Выборка охватывает разнесённые ориентиры сетки и соседние точки примерно на расстоянии её шага.

```bash
python -m weather_coverage collect --round dense-next --stage dense \
  --grid 500 --max-points 20 --endpoints forecast
```

Полное окно опроса одного среза ограничено 12 минутами, чтобы ограничить влияние смены выпуска прогноза и текущих условий. Запуск большой плотной выборки следует планировать отдельно по продуктам и с учётом окна. Сетку можно построить и просмотреть независимо от бюджета.

## Источники географии

Границу и акваторию представляют отношения OSM [4139922](https://www.openstreetmap.org/relation/4139922) и [1763103](https://www.openstreetmap.org/relation/1763103). Южные и восточные дополнения и узлы остановок сохранены в `osm/`. Их адреса и SHA-256 приведены в [реестре](osm/sources.json). Северные и центральные выгрузки взяты из [масштабного манифеста проекта](../data/pkc/scale-manifest.json). Данные OSM распространяются по ODbL. [© OpenStreetMap contributors](https://www.openstreetmap.org/copyright)

Высоты используют имеющийся тайл N53 E158 цифровой модели поверхности Copernicus GLO-30, вертикальная основа EGM2008. На юге ниже 53° с. ш. высота остаётся пустой. [Описание Copernicus DEM](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)
